## 1. 배경

만다라트는 목표 1개를 영역 8개·액션 64개로 나누는 데서 끝납니다. 64칸이 채워진 뒤 실제로 막히는 지점은 **"그래서 오늘 뭘 하지?"**, **"계획대로 가고 있나?"**, 그리고 만다라트가 여러 개일 때 **"지금 무엇이 진행 중이지?"** 입니다.

1. **대시보드** — 진행 중이거나 지난 만다라트를 한곳에서 보고 선택·관리한다.
2. **계획 수립** — 선후관계에 따라 지금 할 수 있는 일을 추천해 투두리스트로 만들고, 일정을 넣고, 간트 차트에서 끌어서 조정한다.
3. **모니터링** — 진행 상황을 글로 보고하면 퍼센트로 읽고, 상황에 맞춰 계획 변경을 추천하고, 이메일로 리마인드한다.

### 1.1 현재 코드베이스 현황 (조사 결과)

**이미 있는 것**

| 영역 | 위치 | 내용 |
|---|---|---|
| 의존성 그래프 | `lib/graph.ts` | `computeReadiness`(ready/blocked/done), `unlockedBy`, `suggestedOrder`, `breakCycles`, `isAcyclic`, `isComplete` — 테스트 17개 |
| 진행 해석 AI | `lib/actions.ts` `readProgressFromText` | 자유 서술 → 5단계(0·10·25·50·75·100) 스냅, 신뢰도, 확인 필요 여부 |
| 계획 리뷰 AI | `lib/actions.ts` `reviewPlan` | 중복·불균형·주당 시간 추정·누락 관점 |
| 실행 순서 화면 | `components/execution-order.tsx` | 지금 시작 가능 / 대기 중 목록 |
| 로컬 초안 목록 | `components/recent-drafts.tsx` | 이 브라우저의 초안(24시간) — 계정과 무관 |
| 스키마 | `supabase/schema.sql` | `actions.due_date`·`cadence`·`progress`, `progress_logs`, `action_dependencies`, 소유자 RLS, `plans`·`actions`의 `updated_at` 자동 갱신 트리거, `plans (owner_id, updated_at desc)` 인덱스 |

**없는 것 — 이 기능들의 전제 조건**

| 문제 | 영향 |
|---|---|
| **완성된 플랜이 Supabase에 저장되지 않음.** `createPlan`은 빈 `plans` 행만 만들고, `savePlanContent`는 어떤 컴포넌트도 호출하지 않음 | 대시보드에 보여줄 서버 데이터가 없음. 기기를 바꾸면 플랜이 없음. 스케줄러가 읽을 데이터가 없어 이메일 불가 |
| **`savePlanContent`를 그대로 연결하면 이력이 지워짐.** 저장마다 서브목표를 삭제 후 재삽입 → `on delete cascade`로 액션·의존성·**진행 보고 이력 전부 삭제**. 의존성은 저장하지도 않음 | 저장 방식을 **ID를 유지하는 upsert**로 바꿔야 함 |
| "내 만다라트" 목록·대시보드 없음. 계정 메뉴에는 로그인/로그아웃만 있음 | 로그인 사용자가 자기 플랜으로 돌아올 경로가 없음 |
| `plans.status`가 `draft/active/archived`뿐 | "완료" 상태를 표현할 수 없음 (§8 D8) |
| `plans.updated_at` 트리거는 **plans 행 자체**가 바뀔 때만 동작 | 액션 편집·진행 보고가 "최근 활동"에 반영되지 않음 (FR-8.4) |
| `due_date`·`cadence`·`progress_logs`를 쓰는 코드 없음 | 스키마만 준비됨 |
| 이메일·스케줄러 인프라 없음 | 새로 구축 (§8 D2·D3) |
| 날짜·간트·드래그 라이브러리 없음 | §7 평가 |
| 액션 수가 **8×8로 고정** (`position between 0 and 7`) | 분할/병합 설계에 영향 (§4, §8 D1) |

## 2. 목표

- **G0.** 로그인 사용자가 자신의 모든 만다라트를 한 화면에서 보고, 골라 들어가고, 정리(보관·삭제·복제)한다.
- **G1.** 만다라트 완성 직후 "지금 할 수 있는 일"을 우선순위와 함께 받고, 그대로 투두리스트로 쓴다.
- **G2.** 일정을 넣을 수 있는 항목은 날짜를 갖고, 간트 차트에서 **끌어서** 일정과 기간을 조정한다.
- **G3.** 진행 보고가 글 한 줄로 끝나고, 앱이 그것을 퍼센트로 읽어 진척에 반영한다.
- **G4.** 계획이 현실과 어긋날 때 앱이 먼저 알아채고 변경안을 **제안**한다. 적용은 항상 사용자가 결정한다.
- **G5.** 앱을 열지 않아도 이메일이 보고 시점을 알려준다.

## 4. 핵심 개념과 데이터 모델

### 4.1 액션과 태스크 — **D1 결정 대기**

분할·병합 요구 때문에 두 가지 길이 있습니다.

```
(a) 태스크 계층 신설 (권장)          (b) 액션 단위로 진행
plan                                  plan
└── subgoal ×8   (고정)               └── subgoal ×8   (고정)
    └── action ×8 (고정)                  └── action ×8 (고정 — 일정·진행을 액션에)
        └── task ×1..n (분할·병합·일정)        ※ 분할·병합은 보류하거나 8×8 제약 해제 필요
```

- **(a)**: 만다라트(8×8)는 "무엇을"의 안정된 지도, 태스크는 "어떻게"의 변하는 목록. 완성 시 액션마다 태스크 1개 생성, 액션 진척 = 태스크 롤업.
- **(b)**: 구조는 단순하지만 분할·병합이 8×8 제약과 충돌. 9×9 접근성 그리드·PDF·PPTX·CSV가 모두 8×8을 전제함.

**분할·병합만이 태스크 계층을 요구합니다.** 분할·병합을 뒤로 미룬다면 일정·간트·모니터링은 (b) 액션 단위로 먼저 진행할 수 있습니다.

### 4.2 D1과 무관하게 필요한 변경

| 대상 | 변경 | 이유 |
|---|---|---|
| 저장 경로 | `savePlanContent`를 **ID 유지 upsert**로 교체, 의존성 저장 추가 | 저장할 때마다 진행 이력이 cascade 삭제됨 |
| `plans.status` | `completed` 추가 (D8) | 대시보드 "완료" 표시 |
| `plans` | `archived_at`, `completed_at`, `last_activity_at` | 대시보드 필터·정렬. `last_activity_at`은 자식 테이블 변경·보고 시 갱신 |
| `plans` | `tracking_started_at` | 후속 단계 진입 시점 |

## 6. 기능 요구사항

### 6.0 전제 — 플랜 영속화

- **FR-0.1** 로그인 사용자의 만다라트는 작성 중에도·완성 후에도 서브목표·액션·의존성을 Supabase에 저장한다.
- **FR-0.2** 저장은 **기존 행의 ID를 유지**한다. 저장이 진행 보고 이력·의존성·태스크를 지우지 않는다.
- **FR-0.3** 익명으로 만든 뒤 로그인한 초안(`claimDraft`)도 같은 경로로 저장된다.
- **FR-0.4** 로그인 사용자의 `/plan/[id]`는 서버에서 읽는다. localStorage는 오프라인 보조로만 쓴다.
- **FR-0.5** 후속 단계 화면은 서버에서도 소유자만 접근 가능하다 (UI 숨김이 아니라 RLS와 라우트에서 강제).

### 6.1 우선순위 분석 & 투두리스트 — D1 대기

- **FR-1.1** 완성 시 투두 항목을 만들고 의존성을 상속한다 (D1에 따라 태스크 또는 액션).
- **FR-1.2** **지금 가능 / 대기 중(선행 필요) / 완료**로 분류. 기준은 `computeReadiness`와 동일.
- **FR-1.3** "지금 가능"을 결정적 점수로 정렬하고 항목마다 근거 한 줄: 풀리는 후속 수(`unlockedBy`), 마감 임박도, 뒤처진 영역 가산.
- **FR-1.4** (D6) AI 우선순위 재검토.
- **FR-1.5** 보기: **오늘 / 이번 주 / 대기 중 / 완료**. 필터: 영역(8색), 마감.
- **FR-1.6** **드래그로 순서 변경** (`@dnd-kit/sortable`). 키보드로도 동일 조작 가능. 완료 체크, 수동 추가·삭제(12초 Undo).
- **FR-1.7** 선행관계 추가·제거. 순환이 생기면 거부하고 이유 표시.

### 6.2 일정 계획 — D1 대기

- **FR-2.1** 항목은 `시작일`·`마감일`·`예상 기간`을 **선택적으로** 가진다. 일정 없는 항목도 정상.
- **FR-2.2** 자동 배치: 시작일을 고르면 의존성을 따라 가장 이른 시작/종료일 계산(전방 패스). **오픈소스 간트판에는 자동 스케줄링이 없으므로 `date-fns` 위에 직접 구현**(§7). 예상 기간 없는 항목은 "일정 미정".
- **FR-2.3** 자동 배치는 **미리보기 → 적용**. 사용자가 직접 입력했거나 끌어서 정한 날짜는 고정되어 덮어쓰지 않는다.
- **FR-2.4** 선행 항목보다 먼저 시작하는 일정은 경고(막지는 않음).
- **FR-2.5** 날짜 계산은 `date-fns` + `@date-fns/tz`. 사용자 시간대 기준 저장·표시.
- **FR-2.6** 플랜별 설정: **달력일 / 근무일(주말 제외)**. 기본 달력일.

### 6.3 간트 차트 — D1 · D9 대기

- **FR-3.1** 일정 있는 항목을 가로 막대로 표시. 행 그룹 = 영역(기존 8색).
- **FR-3.2** 축 단위: 일 / 주 / 월.
- **FR-3.3** 오늘 선, 진척률 채움, 마감 초과 강조, 선행관계 화살표.
- **FR-3.4** **드래그 앤 드롭**:
  - 막대를 끌어 일정 이동
  - 막대 끝을 끌어 기간 변경
  - (라이브러리 지원 시) 막대끼리 연결해 선행관계 추가
- **FR-3.5** 드래그 결과는 즉시 저장하고 **Undo**를 제공한다. 선행관계를 위반하는 이동은 경고하고, 후속 항목을 함께 밀지 사용자가 고른다.
- **FR-3.6** "일정 미정" 항목은 차트 아래 목록. 목록에서 차트로 끌어 일정을 부여할 수 있다.
- **FR-3.7** 막대 클릭 → 편집 패널(일정·진척·분할·병합).
- **FR-3.8** **접근성**: 드래그만으로 가능한 조작은 없어야 한다. 같은 정보를 **표(`<table>`)로 보는 전환**과, 표에서 날짜를 편집하는 대체 수단을 제공. 키보드로 막대 간 이동. 색만으로 상태를 전달하지 않는다.
- **FR-3.9** 좁은 화면에서는 목록 보기로 대체.
- **FR-3.10** ko/en/fi 로케일(월·요일 이름, 날짜 형식).

### 6.4 진행 보고 (모니터링) — D1 대기

- **FR-4.1** 항목마다 진행 보고: 자유 서술 → `readProgressFromText` → 근거와 함께 표시 → **확인 후 저장**.
- **FR-4.2** 신뢰도 <0.5면 확인 강제, 5단계 중 직접 선택 가능.
- **FR-4.3** 원문·해석값·확정값을 `progress_logs`에 누적. 덮어쓰지 않음.
- **FR-4.4** 진척 롤업: 항목 → (액션) → 영역 → 플랜. 9×9 그리드에 진척 채움(기존 `progress` prop).
- **FR-4.5** 보고 이력 타임라인.

### 6.5 계획 변경 추천 — D1 · D6 대기

- **FR-5.1** 결정적 감지 규칙(비용 없음): **지연**(경과 대비 진척 부족), **정체**(N일 보고 없음), **마감 초과**, **병목**(다수 후속을 막음), **과부하**(같은 주 예상 기간 과다).
- **FR-5.2** (D6) AI 변경안: 일정 조정 / 분할 / 병합 / 보류 / 순서 변경 — 구체적 변경 내용과 근거 포함.
- **FR-5.3** 제안은 카드, **항목별 수락/거절**. 수락 전엔 계획 불변. 수락 시 변경 전후 표시, 되돌리기.
- **FR-5.4** 거절한 제안은 같은 조건에서 반복하지 않음.
- **FR-5.5** 제안·결정은 `plan_suggestions`에 기록.

### 6.6 분할 / 병합 — D1 대기

- **FR-6.1** **분할**: 1개 → 2~5개. 선행은 첫 조각에, 후속은 마지막 조각에 연결. 진척·이력 배분 방식은 사용자가 선택.
- **FR-6.2** (D6) AI 분할 초안 → 편집 후 적용.
- **FR-6.3** **병합**: 2개 이상 → 1개. 의존성 합집합·자기 참조 제거, 일정은 최초 시작~최종 마감, 이력 모두 보존.
- **FR-6.4** 분할·병합 후 순환이 생기면 적용하지 않음.
- **FR-6.5** Undo 가능.

### 6.7 이메일 리마인더 — D2 · D3 대기

- **FR-7.1** **옵트인**, 기본 꺼짐. 설정: 주기(매일 요약/주간 점검), 요일, 시각, 시간대, 언어. 대시보드에서 플랜별로 켜고 끔.
- **FR-7.2** 내용: 오늘/이번 주 할 일, 마감 임박·초과, 정체 항목, **"진행 보고하기" 링크**.
- **FR-7.3** 링크는 로그인 후 보고 화면으로. **세션·자동 로그인 토큰을 메일에 넣지 않는다.**
- **FR-7.4** 모든 메일에 **원클릭 수신거부**(서명 토큰, 로그인 불필요)와 설정 링크.
- **FR-7.5** 보낼 내용이 없으면 보내지 않는다.
- **FR-7.6** `dedupe_key`로 스케줄러 재시도에도 1통.
- **FR-7.7** 실패 기록·재시도 한도, 반복 반송 시 자동 비활성화.
- **FR-7.8** ko/en/fi, 텍스트 대체본 포함.

### 6.8 대시보드 — **보류 결정과 무관, 먼저 진행 가능**

만다라트가 여러 개일 때 "지금 무엇이 진행 중인지"를 한눈에 보고 골라 들어가는 첫 화면입니다.

**진입과 구성**

- **FR-8.1** 경로 `/dashboard`. 로그인 사용자 전용(서버에서 강제). 계정 메뉴와 헤더에 "내 만다라트" 링크. 로그인 직후의 기본 도착 화면.
- **FR-8.2** 상단 요약: 진행 중 N개 · 완료 N개 · 이번 주 할 일 수(추적 기능 이후) · 가장 최근 활동.
- **FR-8.3** 본문: 만다라트 카드 목록(좁은 화면은 한 줄 목록). 카드마다:
  - 메인 목표, 언어
  - 상태 배지 — **작성 중 / 진행 중 / 완료 / 보관** (색과 텍스트 함께)
  - 전체 진척률(%) 막대와 완료 액션 수(예: 23/64)
  - 영역 8개 미니 진척 표시(8색)
  - 다음 할 일 1개(추적 기능 이후)
  - 최근 활동일, 생성일
- **FR-8.4** "최근 활동"은 플랜·서브목표·액션 편집과 진행 보고를 모두 반영한다 (`plans.updated_at` 트리거는 플랜 행만 감지하므로 `last_activity_at`을 별도 갱신).

**찾기**

- **FR-8.5** 상태 탭: 전체 / 진행 중 / 완료 / 보관. 기본은 **진행 중**, 없으면 전체.
- **FR-8.6** 정렬: 최근 활동(기본) / 생성일 / 진척률 / 이름.
- **FR-8.7** 메인 목표 텍스트 검색.
- **FR-8.8** 선택한 탭·정렬은 기억한다.

**선택과 관리**

- **FR-8.9** 카드 선택 → 상태에 맞는 화면으로: 작성 중이면 편집기의 해당 단계, 완성이면 계획/모니터링 화면(추적 기능 전에는 기존 시각화).
- **FR-8.10** 카드별 관리 메뉴:
  - **이름 변경**(메인 목표 수정)
  - **보관 / 복원** — 보관은 목록에서 숨기되 데이터 유지
  - **완료로 표시 / 진행 중으로 되돌리기**
  - **복제** — 같은 구조로 새 만다라트 시작(진척·보고는 복사하지 않음)
  - **삭제** — 영구 삭제. 목표 이름을 확인하게 하고, 진행 보고 수를 알려준 뒤 실행. 보관을 먼저 권한다
- **FR-8.11** 여러 개 선택 후 일괄 보관·복원.
- **FR-8.12** 즐겨찾기(핀) — 상단 고정.

**로컬 초안과의 관계**

- **FR-8.13** 이 브라우저에만 있고 계정에 저장되지 않은 초안이 있으면 대시보드 상단에 "계정에 저장하지 않은 만다라트 N개" 안내와 **계정에 저장** 버튼 (`claimDraft` 경로 재사용).
- **FR-8.14** 저장 후 중복 표시하지 않는다.

**빈 상태와 한도**

- **FR-8.15** 만다라트가 없으면 새로 만들기 안내.
- **FR-8.16** "새 만다라트" 버튼은 로그인 사용자 일일 한도(`USER_DAILY_LIMIT`)를 표시하고, 소진 시 비활성화하며 이유를 보여준다.
- **FR-8.17** 목록은 페이지 단위로 불러온다(`plans (owner_id, updated_at desc)` 인덱스 활용).

**품질**

- **FR-8.18** 목록은 시맨틱 리스트, 관리 메뉴는 키보드로 조작, 상태는 색 외 텍스트로도 전달, 모든 문자열 ko/en/fi.
- **FR-8.19** 삭제·보관·완료 표시는 서버에서 소유자 확인(RLS) 후 실행.

**구현 메모 (v2.2 — 1단계)**

- **관리 메뉴는 대화상자로 구현.** 드롭다운 라이브러리를 추가하지 않고 기존 Radix Dialog를 재사용했습니다. 삭제는 대화상자 안의 두 번째 단계입니다: 진행 보고 수 안내 → "대신 보관" 제안 → 메인 목표를 그대로 입력해야 실행. 이름 일치는 서버에서도 다시 확인합니다.
- **FR-8.2 "이번 주 할 일"·FR-8.3 "다음 할 일"은 추적 기능(3단계) 이후로 미룸.** 카드 막대는 작성 중에는 작성량(N/64), 완성 후에는 진척률을 보여 줍니다.
- **FR-8.17 페이지 단위:** 서버는 플랜을 100개씩, 서브목표·액션을 1000행씩 나눠 읽고, 화면은 24개씩 "더 보기"로 보여 줍니다. 서버 페이지 단위로 자르면 진척률·이름 정렬과 검색이 한 페이지 안에서만 맞기 때문입니다.
- **FR-8.13 로컬 초안 저장 경로:** 이 브라우저가 가진 익명 초안 토큰이 맞으면 `claimDraft`, 아니면 새 행으로 가져오기(`importLocalDraft` — 생성 한도를 쓰지 않음), 계정에 행은 있지만 내용이 비어 있으면 업로드. **다른 계정에서 동기화된 적 있는 사본은 제외**합니다(같은 브라우저를 쓴 다른 사람의 플랜을 복사하지 않도록). ID가 익명 행과 겹치면 새 ID로 저장하고, 다른 계정의 행과 겹치면 거부합니다.
- **공개 공유된 남의 플랜이 섞이지 않도록** 모든 조회·변경에 `owner_id` 조건을 명시합니다(RLS의 공개 읽기 정책 때문).
- **`last_activity_at` 보정:** 컬럼을 추가할 때 기존 플랜이 모두 마이그레이션 시각으로 찍혔습니다. 화면은 `updated_at`과 비교해 이른 값을 쓰고, `schema.sql`에 멱등 보정문을 추가했습니다(다음에 실행할 때 반영 — 지금 실행하지 않아도 화면은 정확).
- 로그인 직후 가져올 익명 초안이 없으면 `/dashboard`로 이동합니다.
- **함께 고친 기존 결함:** 편집기의 "찾을 수 없음" 화면이 번역 키를 그대로 표시하던 문제(`plan.notFound`가 문자열인데 하위 키로 읽음), 24시간 정리가 계정에 저장된 적 있는 로컬 사본(미저장 변경 포함)까지 지우던 문제.

| 테스트 | 저장 upsert·일정 계산·롤업·감지 규칙·대시보드 필터/정렬·중복 발송 방지는 순수 함수로 두고 `node --test` 검증 |
