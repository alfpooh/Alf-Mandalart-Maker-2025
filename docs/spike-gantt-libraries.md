## 결론

**간트는 DHTMLX Gantt Community(MIT)를 권장합니다.** 키보드 포커스 이동, ko/fi 로케일, 영역별 막대 색, 컨테이너 안 스크롤, 끌어서 선후관계 만들기가 설정만으로 동작했습니다. SVAR는 같은 항목마다 추가 작업이 필요했습니다(로케일 직접 작성, 서버 렌더링 끄기, 막대 템플릿, 레이아웃 보정, 포커스 관리).

대가는 **간트 화면에서만** JS가 약 94 kB, CSS가 gzip 약 31 KB 더 무겁다는 점입니다. 다른 화면(`/`, `/dashboard`)의 번들 크기는 빌드에서 변화가 없었습니다.

두 라이브러리 모두 **오늘 선 · Undo · 일정 미정 항목 · 근무일 달력 · 자동 스케줄링은 유료판 기능**입니다. 어느 쪽을 골라도 이것들은 직접 구현하며, PRD §6.2·§6.3에 이미 그렇게 적혀 있습니다.

투두 드래그(`@dnd-kit`)와 날짜 계산(`date-fns` + `@date-fns/tz`)은 기존 권장을 유지합니다.

## 투두 드래그 — `@dnd-kit` ✅

- 마우스와 키보드 모두 재정렬됩니다. Space로 들고, 화살표로 옮기고, Space로 놓고, Esc로 취소합니다.
- 안내 문구를 한국어로 지정할 수 있고, 들기·이동·놓기·취소가 라이브 영역에서 읽혔습니다. 놓은 뒤에도 포커스가 손잡이에 남습니다.
- 손잡이는 `role="button"` · `aria-roledescription="sortable"` · 조작 안내와 연결(`aria-describedby`).
- 투두 페이지(dnd-kit + date-fns + tz 포함)의 First Load JS는 130 kB, 페이지 자체는 27.7 kB입니다.
- 마지막 배포가 2024-12이지만 React 19에서 경고·오류가 없었습니다.

## 날짜 계산 — `date-fns` + `@date-fns/tz` ✅

- 전방 패스(선행 항목이 끝난 다음 날 시작)를 구현해 확인했습니다.
- 근무일 모드로 바꾸면 주말 날짜가 0건이 되고, 선행 때문에 늦춰진 5건이 표시됐습니다.
- 시간대를 서울 · 헬싱키 · 로스앤젤레스로 바꿔도 날짜 단위 일정 결과가 같았습니다(`TZDate`).

## 시험 방법과 한계

- **키보드:** 자동화 도구가 보내는 키 입력에 `code`·`keyCode`가 비어 있어, 세 라이브러리 모두 코드를 담은 키 이벤트를 스크립트로 보내 확인했습니다. 실제 키보드는 코드를 보냅니다.
- **SVAR 끌어서 연결:** 직선 끌기와 단계별 포인터 이벤트 모두 링크를 만들지 못했고, 클릭-클릭으로는 만들어졌습니다. 실제 마우스로 끄는 동작은 확인하지 못했습니다.
- **DHTMLX 이동 거리:** 2일 폭만큼 끌었는데 1일만 이동했습니다. 날짜 반올림 설정 영향으로 보이지만 원인은 확인하지 않았습니다.
- **스크린리더:** 실제 기기 시험은 하지 않았고, 역할·포커스·라이브 영역만 확인했습니다.
- **크기:** Next 빌드의 라우트 표 기준이며, 네트워크 전송량(gzip) 기준 JS 비교는 하지 않았습니다.

## DHTMLX를 고를 경우 3단계에서 할 일

- 화면마다 `Gantt.getGanttInstance()`로 인스턴스를 만들고 언마운트 때 `destructor()`로 해제합니다.
- 막대 `aria-label` · 툴팁 · 기본 편집 창 문구를 ko/en/fi 템플릿으로 바꾸고, 기본 편집 창 대신 우리 편집 패널을 씁니다(FR-3.7).
- 오늘 표시는 셀 음영으로, Undo · 일정 미정 목록 · 근무일 계산 · 자동 배치는 직접 구현합니다(FR-2.2, 2.6, 3.5, 3.6).
- 표 보기와 표에서 날짜 편집(FR-3.8)은 라이브러리와 별도로 만듭니다.
- 간트는 그 화면에서만 불러옵니다.
